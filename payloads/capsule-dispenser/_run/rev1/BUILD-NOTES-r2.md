## 1. The three failures that made the r1 exports unbuildable, and what they were

Round 1 shipped `r7` exports that the three critics could not pass. Two of the
three blocking families had the same root cause and it is worth naming it,
because it is the third time this file has done it:

**a boolean silently ate a part, and nothing failed.** `top_plate_r7` came out
as a 0.81 cm³ Ø9 × 24 conduit stub instead of the 96 cm³ lid+neck. Between the
r7 export and the start of this round, someone edited the source and did the
same thing to `brush_holder` — `SEAT_KEEP`/`HOLD_KEEP` were built as
`Box(800,400,400)` centred at **z = 0**, i.e. 116 mm above the wiper station at
z ≈ −316…−330, so `housing -= (seat & SEAT_KEEP)` subtracted *nothing* (the
wiper seat rebate was silently missing) and `holder &= HOLD_KEEP` returned an
**empty** solid. The source I inherited did not run at all:

```
  File ".../cad/dispenser.py", line 1717, in <module>
    export_step(solids[name], os.path.join(EXPORT_DIR, f"{name}_{REV}.step"))
  File ".../build123d/topology/shape_core.py", line 320, in wrapped
    assert self._wrapped
AssertionError
```

Fixed two ways: the keep half-spaces are now centred on the station in Z, and
**every** part now goes through a `_guard()` that raises `PART EATEN` if the
shape is null or below a per-part volume floor. That is the assembly critic's
requirement #1 ("an assertion in the build that fails the export if any named
part's volume drops below a floor — this failure mode has now bitten twice in
the same file"). It has now bitten three times; it cannot bite silently again.

**The two channels are now equal** — 5.4972 mm² / **68.4 %** on *both* beams,
against r7's asymmetric 46.4 % / 17.1 %. That is exactly the value the r1 critic
predicted for a correct labyrinth ("target the symmetric labyrinth-limited
5.51 mm² / 68.5 % on both beams"), so §4.4's coupling argument is again
symmetric and `beam_margin_pct` is no longer channel-dependent.

**B4.2 vs ECO-5 — the contradiction the critic asked me to resolve, in writing.**
Punch-list B4.2 asks for a Ø2.0 × 60 mm clear cylinder on each beam axis.
ECO-5's labyrinth offsets the outer 2.5 mm of each Ø3.2 tunnel by 0.8 mm in x.
Two Ø3.2 circles offset 0.8 mm intersect in a lens of 5.51 mm² whose *inscribed
coaxial* circle about the nominal axis is Ø0.8 — so **B4.2 as written is
unachievable with ECO-5 as written, and always was.** My resolution: keep ECO-5
(the labyrinth is the dust defence that makes the sacrificial window worth
having) and **restate B4.2 as an AREA test — clear aperture ≥ 5.4 mm² (67 % of
nominal) measured on a 0.02 mm ray grid — which is what the checker now
enforces.** The measured 5.4972 mm² is 99.8 % of the geometric maximum a 0.8 mm
labyrinth permits. `ELECTRONICS.md` ECO-5 and punch-list B4.2 should both be
amended to that wording; I have not edited `ELECTRONICS.md` (out of my lane).

**ECO-4 spec-vs-geometry conflict, recorded not papered over.** ECO-4 asks for
the window "flush with the chute wall at y = ±11". A **flat** Ø6 disc cannot be
flush with a Ø22 cylinder: across the Ø6 footprint on the x = 29 chord the bore
surface runs from |y| = 9.468 to 10.995, a sagitta of **1.527 mm**. What is
built instead: the window's inner face sits at exactly |y| = 11.000 — the bore's
own maximum radius — so **nothing is ever proud of the bore** (measured minimum
bore radius 10.9944 with all four windows fitted), and the residual recess is an
*open lune with no undercut and no lip*, reachable by a swab run down the bore
rather than a re-entrant pocket. That is the maintenance property ECO-4 exists
to create; the literal word "flush" is geometrically impossible and
`ELECTRONICS.md` §4.5 should say so.

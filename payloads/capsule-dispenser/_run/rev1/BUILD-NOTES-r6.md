## 2. I-1 — the duct, and the boolean that silently did nothing

This is the finding worth reading even if you skip the rest, because the defect
class is a property of the CAD kernel, not of the design.

The round-5 critic's diagnosis was exact and I reproduced it before changing
anything. On the r11 model, in a session that exec'd `dispenser.py` up to the
line before the subtraction:

```
rp vol before cut 80301.8148310599
bore vol 7952.35027894966 nsolids 1
inter(rp,bore) 0.0
rp vol after cut 80301.81494948467
```

(the diagnostic also printed a wall-clock `cut time` line, elided here because
it is a timing and not a measurement — the boolean *ran*, it just did nothing)

The intersection of two solids that visibly overlap reads **0.0 mm³**, and the
cut *adds* 0.0001 mm³ of numerical noise instead of removing 7952 mm³. A Ø1
sphere placed on the duct axis, meanwhile, reads inside **both**:

```

bore.intersect(duct) 0.0

single cyl vol 382.8816046562563 inter rp 343.61169648638395
rp - singlecyl 79958.20313401545
bore wrapped type TopAbs_ShapeEnum.TopAbs_COMPOUND
```

A **single** cylinder cuts correctly (343.6 mm³ removed). The fuse does not. One
line explains it:

```

duct valid= True

```

`BRepAlgoAPI` returns an empty shape when the tool is invalid, and raises
nothing. Every downstream number — part volume, mass, the ledger, the harness
coverage metric — was self-consistent with a fix that was not in the geometry.

`cut_each()`; the duct bores are a list, each is validity-checked, each is cut

line of the run:

(The 13.40 vs 13.50 is the 0.1 mm probe step. B9c asks ≥ 6 mm; both pass.)

deliberately not taken: it would have required me to state a heat-set bore

self-check is a grid scan of the whole barrel bore. The old check is kept, with
